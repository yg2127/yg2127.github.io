## 큐에서 차례가 밀린다는 설명

그래프 순회 노트에는 개념 목록 뒤에 내 말로 길게 풀어 쓴 문장이 남아 있다.

> DFS에서는 재귀적으로 바로 처리하는데 BFS에서는 큐에 넣고 큐에서 나오는 과정에서 그 간선 노드의 반대편 정점의 간선 노드들을 큐에 inqueue하는거야.(재귀랑 엇비슷) 그러면 처리 순서가 맨 뒤로 가게 되고 기존에 추가되었던 간선들 먼저 처리가 되는거지!

바로 앞에는 “이해가 드디어 됐어!”라고 적었다. 이 기록에서 이해가 바뀐 지점은 DFS는 스택, BFS는 큐라는 대응표보다 구체적이다. **다음 정점을 지금 처리하느냐, 뒤에 넣어 두고 기존 작업을 먼저 처리하느냐**를 구분했다.

다만 같은 노트의 “BFS에서는 재귀적으로”라는 표현은 정리할 필요가 있다. 여기서 구현할 BFS는 재귀 호출 없이 큐와 반복문으로 동작한다. 서로 닮은 것은 이웃의 이웃으로 탐색이 이어진다는 점이고, 실제 호출 방식과 처리 순서는 다르다. 이번에는 노트의 설명을 C 코드로 다시 구성해 그 차이를 따라갔다.

## 같은 그래프에서 다음 작업을 고른다

이웃을 번호 오름차순으로 살피는 무방향 그래프를 사용하자.

```text
0의 이웃: 1, 2
1의 이웃: 0, 3
2의 이웃: 0, 3
3의 이웃: 1, 2
4의 이웃: 없음
```

DFS가 0에서 1을 만나면 0의 나머지 이웃인 2를 잠시 남겨 두고 `dfs(1)`로 들어간다. 1에서 3, 3에서 2로 들어간 뒤 더 갈 곳이 없으면 호출을 거꾸로 빠져나온다. 방문 순서는 `0 1 3 2`다.

```c
static void dfs_visit(const Graph *g, int u, bool visited[N], int order[N], int *count) {
    visited[u] = true; order[(*count)++] = u;
    for (Node *p = g->adj[u]; p; p = p->next)
        if (!visited[p->vertex]) dfs_visit(g, p->vertex, visited, order, count);
}
```

`p = p->next`는 같은 정점의 다른 이웃으로 이동한다. 반면 재귀 호출은 `adj[p->vertex]`의 이웃들을 살펴보러 들어간다. 재귀에서 돌아왔을 때 이전 호출의 `p`가 남아 있으므로 보류한 이웃 검사를 이어 갈 수 있다.

여기서는 정점의 방문 여부를 표시한다. 원문에 “간선 방문시 1”이라고 적은 대목이 있지만, 정점을 한 번씩 탐색하려는 이 구현에서 배열 인덱스는 간선이 아니라 정점 번호다.

## BFS는 발견했을 때 자리를 예약한다

BFS는 0의 이웃 1과 2를 모두 큐 뒤에 넣는다. 그다음 1을 처리하면서 3을 발견해도, 3은 이미 기다리고 있는 2보다 뒤에 들어간다.

| 방금 처리한 정점 | 처리 뒤 대기 중인 큐 | 새로 발견한 정점 |
| --- | --- | --- |
| 0 | 1, 2 | 1, 2 |
| 1 | 2, 3 | 3 |
| 2 | 3 | 없음 |
| 3 | 비어 있음 | 없음 |

그래서 순서는 `0 1 2 3`이다. 2를 처리할 때도 이웃 3이 보이지만 다시 큐에 넣지 않는다. **꺼낼 때가 아니라 넣을 때 이미 발견했다고 표시했기 때문**이다.

```c
static int bfs(const Graph *g, int start, int order[N], int dist[N], int parent[N]) {
    int queue[N], head = 0, tail = 0;
    for (int v = 0; v < g->n; ++v) { dist[v] = -1; parent[v] = -1; }
    dist[start] = 0; queue[tail++] = start;
    while (head < tail) {
        int u = queue[head]; order[head++] = u;
        for (Node *p = g->adj[u]; p; p = p->next) {
            int v = p->vertex;
            if (dist[v] != -1) continue;
            dist[v] = dist[u] + 1; parent[v] = u;
            queue[tail++] = v;
        }
    }
    return tail;
}
```

`dist[v] == -1`은 아직 발견하지 않았다는 뜻이다. 큐에 넣기 직전에 거리를 기록하므로 정점 하나가 여러 부모 후보에게 중복 예약되지 않는다. 정점이 V개면 큐에 들어가는 횟수도 최대 V회라 이 예시의 고정 배열 큐로 충분하다. `N=16`은 검증 프로그램의 입력 한도이며, 실제 입력을 받는 프로그램에서는 그 크기를 맞춰 할당해야 한다.

## 거리가 함께 나오는 이유

큐에는 출발점에서 간선 하나로 닿는 정점들이 먼저 쌓이고, 그다음 두 개, 세 개로 닿는 정점들이 쌓인다. u를 처리하며 v를 처음 발견했다면 `dist[v] = dist[u] + 1`이다. 더 적은 간선으로 v에 도착할 수 있었다면 더 앞 단계에서 이미 발견했어야 한다.

이번 실행은 다음과 같았다.

```text
DFS: 0 1 3 2
BFS: 0 1 2 3
BFS distances: 0 1 1 2 -1
```

여기서 거리는 **간선 개수**다. 가중치가 제각각인 그래프의 요금이나 시간을 최소화한 값이 아니다. 0→2가 100원이고 0→1→3→2가 총 3원이어도 BFS는 한 간선짜리 경로를 먼저 발견한다. 가중치가 같은 경우에만 간선 수 최소화와 비용 최소화가 일치한다. [Algorithms, 4th Edition의 BFS와 최단 경로 설명](https://algs4.cs.princeton.edu/41graph/)

`parent[v]`는 처음 발견한 간선의 출발 정점을 기록한다. 위 실행에서 3의 부모는 1이므로 3→1→0을 거꾸로 따라가 경로를 복원할 수 있다. 이웃 순서를 바꾸면 최단 경로 후보 중 다른 부모를 고를 수 있지만 최소 간선 수는 같다.

## 한 번의 시작으로 모두 방문되지는 않는다

고립 정점 4의 거리는 -1로 남는다. 0에서 출발한 순회는 0과 연결된 부분만 방문한다. 전체 그래프를 빠짐없이 훑으려면 아직 방문하지 않은 정점마다 순회를 다시 시작해야 한다. 무방향 그래프에서는 그 횟수로 연결요소 수도 셀 수 있다.

인접리스트를 사용하는 전체 순회는 O(V+E) 시간이다. DFS는 깊이가 V에 가까워지면 호출 스택도 O(V)까지 늘고, BFS 역시 큐와 거리 배열에 O(V) 공간을 사용한다. 긴 사슬 입력에서는 재귀 호출 한도를 따로 고려해야 한다.

새 검증에서는 정점 4개의 자기 루프 없는 모든 방향 그래프 4,096개를 만들었다. 각 시작점에서 BFS 거리를 별도의 행렬 기반 최단 거리 계산과 비교하고, DFS가 방문한 집합도 같은 도달 가능성과 대조했다. 특정 방문 순서 하나를 외우는 대신, **무엇을 방문해야 하고 거리가 무엇이어야 하는지**를 확인한 셈이다.

노트의 “기존에 추가되었던 간선들 먼저”라는 말은 이제 “먼저 발견해서 큐에 넣어 둔 정점부터 처리한다”로 고쳐 적을 수 있다. 내가 붙잡았던 처리 순서의 감각을 유지하면서, 무엇을 저장하고 표시하는지까지 분명히 하는 정리다.
