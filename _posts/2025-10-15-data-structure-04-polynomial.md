## 마지막 노드가 빠질 수 있다는 기록

`디버깅 기법` 노트에는 두 연결리스트를 연산할 때의 경고가 남아 있다.

> 반복의 조건을 잘 봐야한다. 마지막 노드나 첫번째 노드가 연산에서 제외될 수 있다!

다항식 덧셈 코드를 보면 이 경고가 필요한 지점이 선명하다. 각 항을 `(계수, 지수)` 노드로 만들고 지수가 큰 순서로 연결하면 두 다항식을 앞에서부터 비교할 수 있다.

```text
A = 3x⁴ + 2        → (3,4) → (2,0)
B = -3x⁴ + 5x - 2  → (-3,4) → (5,1) → (-2,0)
```

두 입력은 지수 내림차순이다. 이 정렬이 두 포인터 알고리즘의 전제다. 예를 들어 B를 `(-3,4) → (-2,0) → (5,1)`처럼 넣으면 뒤늦게 더 큰 지수가 나타나 현재 노드끼리의 비교만으로 정렬된 합을 만들 수 없다.

## 두 포인터가 움직이는 세 경우

[저장소의 다항식 덧셈](https://github.com/yg2127/25-1_data_structure/blob/eab0311e196a27d98ca6aa493290c9078f206dbb/%EC%A4%91%EA%B0%84%EB%B2%94%EC%9C%84/6-2.c#L42-L70)은 `curr1`과 `curr2`가 가리키는 지수를 비교한다.

| 비교 | 결과에 넣는 항 | 움직이는 포인터 |
|---|---|---|
| `exp1 > exp2` | A의 현재 항 | `curr1` |
| `exp1 < exp2` | B의 현재 항 | `curr2` |
| `exp1 == exp2` | 계수의 합 | 둘 다 |

같은 지수의 계수를 더한 값이 0이면 그 항은 결과에 넣지 않는다. 여기까지는 두 리스트에 비교할 항이 모두 있을 때만 가능하다.

```c
while (curr1 != tail1 && curr2 != tail2) {
    /* 지수를 비교하고 한쪽 또는 양쪽 포인터를 이동 */
}
```

핵심 while은 **둘 중 하나만 끝나도** 멈춘다. 이때 다른 리스트에 항이 남아 있을 수 있다. 따라서 뒤의 두 반복문은 부가 처리가 아니라 알고리즘의 일부다.

```c
while (curr1 != tail1) { append(curr1); curr1 = curr1->next; }
while (curr2 != tail2) { append(curr2); curr2 = curr2->next; }
```

이 부분이 없으면 공통 구간까지만 계산하고 긴 다항식의 꼬리를 잃는다. 노트의 “마지막 노드가 제외될 수 있다”는 말이 바로 이 종료 조건과 연결된다.

## 끝을 찾는 비용도 함께 보기

원본의 `appendTerm`은 항을 하나 넣을 때마다 Head에서 출발해 마지막 노드를 찾는다. 결과 항이 k개라면 탐색 길이가 0, 1, 2, …로 늘어 전체 작성 비용이 $O(k^2)$가 된다. 두 입력을 한 번씩 훑는 merge 자체는 $O(n+m)$인데, append 구현이 장점을 가린다.

이번에 만든 [tail 포인터 기반 검증 코드](/assets/code/data-structure-study/04-polynomial-merge.c)는 결과의 마지막 노드를 직접 들고 다닌다.

```c
static int append(Node **tail, int coef, int exp) {
    if (coef == 0)
        return 1;
    (*tail)->next = malloc(sizeof(Node));
    if (!(*tail)->next)
        return 0;
    *tail = (*tail)->next;
    **tail = (Node){coef, exp, NULL};
    return 1;
}
```

호출자는 0을 받으면 이미 만든 결과 노드를 해제하고 덧셈을 중단한다.

정렬된 `3x⁴ + 2`와 `-3x⁴ + 5x - 2`를 넣어 다시 실행했다. $x^4$와 상수항은 계수가 0이 되어 사라지고, 한쪽에 남은 `5x`만 결과에 들어갔다.

```text
5x^1
```

이 실행은 이번 글을 위해 새로 만든 검증이다. 결과가 정확히 `(5,1)` 노드 하나이고 다음 노드가 NULL인지 `assert`로도 검사했다. 과거에 같은 입력으로 오류를 재현했다고 해석하지 않는다.

## 더미 노드를 계산에서 제외하기

노트에는 “Head 등의 더미노드를 연산하지 않게 조심해야 한다”는 문장도 있다. 원본 구현이 `Head1->next`, `Head2->next`에서 시작하고 `Tail`에 닿기 전에 멈추는 이유다. 더미 노드는 연결을 편하게 하지만 계수와 지수를 가진 실제 항은 아니다.

경계 입력은 다음처럼 정리할 수 있다.

- 한쪽이 빈 다항식이면 다른 쪽의 모든 항을 복사한다.
- 같은 지수의 합이 0이면 결과 노드를 만들지 않는다.
- 두 리스트가 동시에 끝나지 않아도 남은 항 반복을 계속한다.
- 결과의 tail을 직접 갱신해 append를 상수 시간으로 만든다.
- 동적으로 만든 결과 노드는 출력 뒤 모두 해제한다.

[앞 글의 포인터 변경](/2026/09/data-structure-03-linked-list.html)이 한 리스트 안의 연결을 지키는 문제였다면, 이번에는 두 리스트의 현재 위치와 결과 리스트의 끝을 동시에 지키는 문제였다. 반복문 하나가 끝났다는 사실은 계산이 끝났다는 뜻이 아니었다. 어느 포인터가 왜 끝났고, 다른 포인터에는 무엇이 남았는지를 확인해야 했다.
